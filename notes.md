# Relationships

## Теория

Три основных способа подгрузки отношений:
1. joinedload
2. selectinload
3. contains_eager

Основное отличие `joinedload` и `selectinload` в SQLAlchemy — это способ загрузки связанных данных: `joinedload` использует SQL JOIN в одном запросе, а `selectinload` делает дополнительный запрос с IN, что обычно эффективнее для коллекций. 

`Joinedload` лучше для many-to-one, а `selectinload` — для one-to-many.

Ключевые различия:
- `joinedload()` (объединенная загрузка): 
  - Принцип: Добавляет LEFT OUTER JOIN к основному SQL-запросу.
  - Запросы: Все данные (родитель + связанные) загружаются за один запрос.
  - Лучшее использование: Связи "многие-к-одному" (many-to-one), когда у родителя один связанный объект (например, Post -> User).
  - Минусы: Может возвращать дубликаты строк (требует `unique()`), а при загрузке больших коллекций (one-to-many) запрос становится медленным из-за декартова произведения.
- `selectinload()` (загрузка через IN):
  - Принцип: Делает один основной запрос, а затем — второй, который использует IN для загрузки связанных объектов.
  - Запросы: Два запроса (основной + для отношений).
  - Лучшее использование: Связи "один-ко-многим" (one-to-many) и "многие-ко-многим" (many-to-many), т.е. коллекции.
  - Плюсы: Работает быстрее при выборке большого количества связанных данных, так как не перегружает базу лишними JOIN.
  - Минусы: Не работает с составными первичными ключами.


Как выбрать: 
Используйте `selectinload()` по умолчанию для большинства ситуаций, особенно коллекций. Применяйте `joinedload()`, если связь "многие-к-одному" или если нужно отфильтровать основной запрос по связанной таблице
